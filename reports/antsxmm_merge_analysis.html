⚡ The Seam: How ANTsXMM Currently Drives ANTsPyMM

In antsxmm/pymm_execution.py, ANTsXMM intercepts antspymm.mm_csv using a dynamic context manager: 

# antsxmm/pymm_execution.py:84-152
@contextmanager
def _patched_docsamson(antspymm_module: Any, study_df: pd.DataFrame):
    # ANTsXMM extracts mm_csv.__globals__ and replaces 'docsamson' with deterministic_docsamson
    mm_csv_globals = getattr(mm_csv_fn, "__globals__", None)
    mm_csv_globals["docsamson"] = deterministic_docsamson  # Fragile monkeypatch!
    setattr(antspymm_module, "docsamson", deterministic_docsamson)
    try:
        yield
    finally:
        # Restore original docsamson symbol

Why this was necessary: antspymm.mm_csv() hardcodes calls to docsamson(), which traditionally enforced legacy NRG naming. ANTsXMM patched this symbol at runtime so that output filenames and paths obey the modern deterministic BIDS hierarchy without rewriting mm_csv().
The merger benefit: Merging the two packages allows antspymm.mm_csv() to natively accept deterministic BIDS output prefixes, eliminating monkey-patching completely!

🛠️ Recommended Merge Strategy: 4-Phase Zero-Breaking-Change Roadmap

Phase 1: Native Seam Hooking in ANTsPyMM (Zero Impact on Existing Code)

Update antspymm.mm_csv() to check if the input DataFrame provides deterministic layout columns (xmm_prefix_*) or an optional docsamson_fn callable.

  • If xmm_prefix_* columns are present, mm_csv() directly uses them without needing NRG folder translation.
  • If not present, mm_csv() falls back to standard legacy docsamson().
  • Result: 100% backward compatible for legacy callers; ANTsXMM no longer needs runtime __globals__ mutation.
Phase 2: Subpackage Incorporation (antspymm.xmm)

Incorporate the 24 modern modules of ANTsXMM directly into ANTsPyMM under antspymm/xmm/:

  • antspymm/xmm/bids.py — BIDS layout discovery and entity parsing
  • antspymm/xmm/execution_plan.py — Deterministic execution planning and session graph
  • antspymm/xmm/session.py — Staging, processing, and output validation
  • antspymm/xmm/aggregate.py — Multi-session merged table aggregation
  • antspymm/xmm/cli.py — Rich Click-based CLI (antsxmm run, tree, validate, aggregate)
  • antspymm/xmm/environment.py — Multi-threading and cluster execution policies
Phase 3: Unified Testing & CLI Entrypoints

Integrate the two test suites and register unified CLI console scripts:

  • Register CLI entrypoint in pyproject.toml: 
    [project.scripts]
antsxmm = "antspymm.xmm.cli:main"
antspymm = "antspymm.xmm.cli:main"
  • Add all 112 ANTsXMM regression tests to tests/ in ANTsPyMM.
  • GitHub Actions CI automatically verifies all 133 tests across Python 3.10, 3.11, and 3.12 on every push and pull request.
Phase 4: Backward-Compatibility Shim for Existing ANTsXMM Users

To ensure existing pipelines, SLURM scripts, Docker containers, and conda environments never break:

  • The standalone antsxmm repository becomes a lightweight shim package whose antsxmm/__init__.py simply does: 
    # In antsxmm shim:
from antspymm.xmm import *
from antspymm.xmm import __all__
  • Any user executing pip install antsxmm automatically installs antspymm and continues running identically.
  • Zero disruption for existing scripts: from antsxmm import process_session and from antspymm.xmm import process_session will both work.

✨ Direction A Summary (Embed ANTsXMM in ANTsPyMM)

For End Users

  • Single installation: pip install antspymm installs both the scientific engine and the BIDS CLI.
  • Direct access to modern CLI: antsxmm run BIDS_DIR OUT_DIR works out-of-the-box.
  • No version mismatches between orchestration and processing libraries.

For Maintainers

  • Elimination of brittle monkey-patching in __globals__.
  • A combined 133-test safety net preventing regressions across algorithms and workflows.
  • Single CI workflow and single PyPI release pipeline to manage.

🔄 Direction B: The Inverted Merger — Taking "The Best of ANTsPyMM" into ANTsXMM

What if we go the other way? Instead of bringing ANTsXMM into the 13,389-line legacy monolith, we extract only the scientific gems of ANTsPyMM into clean, modular subpackages inside ANTsXMM, leaving all legacy NRG technical debt behind.

2. What Gets Left Behind (The Legacy Cruft: ~9,000 lines eliminated)

  • Legacy NRG Transcoders: nrg_2_bids, bids_2_nrg, parse_nrg_filename, nrg_format_path, validate_nrg_file_format (ANTsXMM's BIDS parser is already far superior).
  • Legacy Directory Enforcers: mm_nrg (8,300 lines in), ptbp_nrg, docsamson.
  • Double-Indirection: The entire chain of mock DataFrame → monkeypatch docsamson → mm_csv → mm disappears completely! antsxmm/session.py calls the modality functions directly with resolved BIDS paths.
  • Stale Prototypes: Unused novelty detection functions (novelty_detection_ee, novelty_detection_svm, etc.) and broken scratch scripts in docs/.
